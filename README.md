# Сайт Аэрокосмической олимпиады МФТИ

Сайт олимпиады: регистрация участников, дистанционный этап с приёмом решений,
карта площадок очного тура, лекции и архив задач.

Стек: **Python 3.12 + Django 5 + PostgreSQL** (локально SQLite), серверный рендеринг,
карта на Leaflet + OpenStreetMap. Почему именно так — в [docs/architecture.md](docs/architecture.md).

Масштаб, под который всё рассчитано: до тысячи участников, дистанционный этап
длится несколько месяцев, задачи проверяются вручную.

## Никогда не работали с git, Python или Django?

Начните отсюда: **[docs/start-here.md](docs/start-here.md)** — запуск сайта
на своём компьютере по шагам, с нуля, без предварительных знаний.

## Быстрый старт (5 минут, без Docker)

```bash
git clone https://github.com/leeiozh/ao-mipt.git
cd ao-mipt
make start       # поставит зависимости, создаст базу, наполнит и запустит
```

Или по шагам, если хочется понимать, что происходит:

```bash
make install     # создаст .venv и поставит зависимости
make migrate     # создаст базу (SQLite, файл db.sqlite3)
make seed        # наполнит демо-данными
make dev         # http://127.0.0.1:8000
```

Если `make` нет под рукой — то же самое руками:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
sed 's/^DEBUG=False/DEBUG=True/' .env.example > .env
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py runserver
```

Заполнять `.env` для локальной работы не нужно: пустые значения означают
«взять разумное по умолчанию» — база в файле рядом с проектом, письма
печатаются в терминал вместо отправки.

## Показать коллегам, не поднимая сервер

Демо публикуется само после каждого `git push` в `main` — собирает
GitHub Actions, выкладывает на GitHub Pages. Настройка одна:
Settings → Pages → Source → **GitHub Actions**.

Собрать локально, чтобы посмотреть до выкладки:

```bash
make demo        # собирает dist/ — 44 статические страницы
```

Получается папка с настоящими страницами сайта, перелинкованными между собой:
открывается двойным кликом по `dist/index.html`, кидается архивом или
выкладывается на GitHub Pages как есть. Пересобирается одной командой после
любых правок. Подробности — в [docs/demo.md](docs/demo.md).

## Запуск в Docker (как на сервере)

На сервер сайт ставится контейнерами: база, сайт, nginx с HTTPS,
рассылки и ежедневный бэкап — одной командой. Пошагово, от чистого
сервера до работающего https — в [docs/deploy.md](docs/deploy.md).

Проверить сборку у себя:

```bash
cp .env.example .env    # вписать SECRET_KEY, POSTGRES_PASSWORD,
                        # ALLOWED_HOSTS=localhost и USE_HTTPS=False
make up                 # http://localhost
```

## Что где лежит

```
config/            настройки Django, корневые URL
apps/
  core/            базовые модели, главная страница, проверки файлов
  accounts/        пользователи (вход по e-mail), анкета участника, роли
  seasons/         сезон, этапы и их даты (schedule.py)
  venues/          площадки очного тура, карта, модерация заявок
  participation/   участие в сезоне, запись на площадку
  contest/         задачи, решения, оценки
  content/         новости, лекции, плейлисты, страницы, архив
  mailing/         рассылки участникам
templates/         HTML-шаблоны
static/
  css/tokens.css   ВСЕ цвета и шрифты — файл для дизайнера
  css/main.css     вёрстка (цветов не содержит)
deploy/            всё для сервера: nginx, бэкап, настройка сервера, HTTPS
docs/              архитектура, дорожная карта, инструкция по развёртыванию
```

## Повседневные команды

```bash
make help        # список всех команд
make test        # тесты
make lint        # проверка стиля
make migrations  # создать миграции после правки моделей
make superuser   # создать администратора

.venv/bin/python manage.py import_archive --dry-run   # импорт архива прошлых лет
.venv/bin/python manage.py fetch_playlist_covers      # обложки плейлистов с YouTube
.venv/bin/python manage.py send_newsletters           # отправить порцию писем из очереди
```

## Как вносить изменения

1. Новая ветка: `git checkout -b venue-booking`.
2. Правим код. После изменения моделей — `make migrations` и `make migrate`.
3. `make test` и `make lint` должны быть зелёными.
4. Пул-реквест, ревью, мердж в `main`.

Секреты (`SECRET_KEY`, пароли, SMTP) живут только в `.env` и никогда не коммитятся.
Список нужных переменных — в `.env.example`.
