# Как показать сайт коллегам

Три способа, от самого быстрого к самому основательному.

## 1. Статический снимок — 30 секунд

```bash
make demo
```

Команда выгружает настоящий сайт в 44 статические HTML-страницы в папку `dist/`:
главная, регистрация участника и организатора, дистанционный этап, страницы
задач, карта площадок, архив за шесть сезонов, лекции, правила, согласие на
обработку данных.

Что с этим делать:

* открыть `dist/index.html` двойным кликом — работает без интернета и без сервера;
* заархивировать папку и отправить в мессенджере;
* выложить на GitHub Pages (см. ниже).

Данные берутся из демонстрационной базы (`make seed` + `import_archive`),
поэтому реальные персональные данные в снимок попасть не могут.

Наверху каждой страницы — полоса «Демонстрационная версия», чтобы никто не
принял снимок за рабочий сайт.

### Чего в снимке нет

* **Формы не отправляются.** Сервера за страницами нет, кнопки ничего не делают.
* **Админки нет.** Она под паролем и в снимок не попадает — её показывайте вживую
  через `make dev`.
* **Карта работает**, потому что тянет тайлы с OpenStreetMap — нужен интернет.
  На Pages она рисуется именно OpenStreetMap: ключ Яндекс.Карт в сборку не
  передаётся, ему там взяться неоткуда и незачем.
* **Фотографии финалов и обложки плейлистов переносятся** вместе со
  страницами. А вот решения участников — никогда: это персональные данные,
  и отдельный тест следит, чтобы они не утекли в публичный снимок.

## 2. GitHub Pages — ссылка, которую можно кинуть в чат

Собирается и выкладывается само, руками ничего делать не нужно: после
каждого `git push` в `main` GitHub Actions поднимает сайт у себя,
наполняет демо-данными, выгружает в статику и публикует.

Файл сборки: `.github/workflows/pages.yml`.
Адрес: `https://<аккаунт>.github.io/<репозиторий>/`.

**Одна настройка, без которой это не заработает:**
Settings → Pages → Source → **GitHub Actions** (не «Deploy from a branch»).
Если там стоит ветка, Pages будет искать `index.html` в корне репозитория,
а его там нет — в корне лежит код Django.

Пересобрать вручную, не делая коммит: вкладка **Actions** → «Демо на
GitHub Pages» → **Run workflow**.

Собрать снимок локально, чтобы посмотреть до выкладки:

```bash
make demo   # -> dist/
```

Важно: **GitHub Pages публичен для всех.** В снимке только демонстрационные
данные, так что ничего страшного, но проверьте это перед каждой выкладкой.
Если нужна закрытая ссылка — приватный репозиторий Pages требует платного
тарифа, проще воспользоваться первым или третьим способом.

## 3. Живой сайт — когда нужно показать админку

```bash
make dev
```

Дальше `http://127.0.0.1:8000`, вход `admin@example.ru` / `olymp12345`.

Это единственный способ показать то, ради чего всё затевалось: как
администратор заводит сезон, публикует задачи, одобряет площадки и
отправляет рассылку. Формы работают, файлы загружаются.

Если коллега в той же сети, можно открыть доступ:

```bash
.venv/bin/python manage.py runserver 0.0.0.0:8000
```

и добавить свой IP в `ALLOWED_HOSTS` в `.env`. Только для показа внутри
своей сети — не выставляйте сервер разработки в интернет.

## Что показывать в каком порядке

Если у вас пятнадцать минут на демонстрацию:

1. **Главная** — анонс сезона, обратный отсчёт до дедлайна.
2. **Регистрация** — обратите внимание на ссылки в галочке согласия.
3. **Дистанционный этап и страница задачи** — как школьник сдаёт решение.
4. **Карта площадок** — и форма заявки организатора с точкой на карте.
5. **Архив** — шесть сезонов, импортированных автоматически.
6. **Админка** (вживую): создание задачи, одобрение площадки, рассылка
   с подтверждением числа получателей.

Шестой пункт производит наибольшее впечатление на тех, кто будет
пользоваться сайтом каждый день: становится видно, что весь сезон
ведётся кликами, без программиста.
