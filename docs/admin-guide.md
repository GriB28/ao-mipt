# Руководство администратора

Пошагово: как войти, завести организатора, опубликовать задачу и проверить решения.
Всё описанное делается в браузере, без программиста.

---

## 1. Вход в админку

Запустите сайт:

```bash
make dev
```

Админка: **http://127.0.0.1:8000/admin/**

В демо-базе (`make seed`) уже есть учётные записи, пароль у всех `olymp12345`:

| Почта | Роль | Что видит |
|---|---|---|
| `admin@example.ru` | администратор | всё |
| `organizer@example.ru` | организатор | свои площадки, решения и оценки |
| `student@example.ru` | участник | только сайт |

Свою учётку создайте командой:

```bash
make superuser
```

Она спросит почту и пароль. Пароль короче восьми знаков или слишком
простой Django не примет.

**Если админка не открывается и вас выбрасывает на страницу входа** —
у пользователя не стоит флаг «Статус персонала». Без него в админку не
пускает, даже если роль «Администратор». Это защита, а не ошибка.

## 2. Как завести организатора

Организаторы — свои люди, самостоятельной регистрации у них нет.
Админка → **Пользователи** → **Добавить пользователя**.

1. **Почта** и пароль. Пароль потом человек сменит сам через
   «Забыли пароль?» — придумайте временный.
2. **Роль** → «Организатор».
3. Сохранить. Откроется полная форма.
4. Внизу, в блоке **Анкета организатора**, впишите фамилию и имя.
   Больше ничего не требуется.
5. Флаг «Статус персонала» **не ставьте** — организатору админка не нужна.

Передайте человеку почту и временный пароль. Всё.

### Как привязать организатора к площадке

Админка → **Площадки** → нужная площадка → поле **организаторы** →
выбрать пользователя. Организатор видит только те площадки, где он указан
в этом поле.

### Как одобрить площадку

Площадка со статусом «На модерации» не показывается ни на карте, ни в
записи — участник её просто не видит.

Админка → **Площадки**. Заявки на модерации стоят **первыми в списке** и
подсвечены в колонке «статус», искать их глазами не нужно. Отметьте
галочками → выпадающий список действий внизу →
**«Одобрить выбранные площадки»** → Выполнить.

После одобрения площадка сразу появляется на карте, и на неё можно
записываться — при условии, что открыта запись на очный тур
(Сезоны → Этапы → «Очный тур» → «запись открывается/закрывается»).

Если что-то не так с адресом — откройте площадку, впишите
**комментарий модератора** и поставьте статус «Отклонена». Организатор
увидит комментарий у себя в кабинете.

## 3. Как войти под организатором

Организатор входит **не в админку, а на сам сайт**:
http://127.0.0.1:8000/accounts/login/

После входа на каждой вкладке появляется своя панель «Организатору» —
инструменты разнесены по турам, а не свалены в одну кучу:

**«Дистанционный тур»** — всё про задачи:

* «Добавить задачу», «Мои задачи», «Проверить решения».

**«Очный тур»** — всё про площадки:

* кнопка «Добавить площадку»;
* таблица своих площадок: название, город, статус, сколько записалось.
  Название — ссылка на площадку, оттуда открываются списки, баллы,
  правка и письмо участникам.

Администратор видит в таблице все площадки, организатор — только те,
где он указан в поле **организаторы** карточки площадки.

Чтобы проверить это самим, выйдите из своей учётки и войдите как
`organizer@example.ru` / `olymp12345`.

### Добавление площадки организатором

Вкладка **«Очный тур»** → панель «Организатору» → **Добавить площадку**
(или сразу `/offline/apply/`). Форма: название, регион,
город, адрес, контакты — и **клик по карте**, чтобы отметить положение
школы. Координаты подставятся сами.

Площадка создаётся со статусом «На модерации» и ждёт вашего одобрения.
Участникам она до этого не видна.

Обычный участник эту страницу открыть не сможет — получит отказ доступа.

## 4. Как добавить задачу

**На сайте:** вкладка «Дистанционный тур» → панель «Организатору» →
**Добавить задачу**. Внизу формы две кнопки:

* **Сохранить черновик** — задача видна только вам, можно дописывать;
* **Отправить на одобрение** — уходит администратору.

**Участники видят задачу только после одобрения администратором и не
раньше начала этапа.** Все задачи этапа открываются одновременно в момент
его начала: время задаётся одно на весь этап — Админка → **Сезоны →
Этапы** → поле «начало». Отдельного времени публикации у задачи нет.
Пока статус «Черновик», «На одобрении» или «Отклонена», задачи нет ни в
списке, ни в архиве.

Условие — только текстом на странице (PDF в форме нет: его не прочитать
с телефона). Разбор после тура прикладывает администратор в админке.

Условие пишется прямо в форме. **Формулы — в долларах**, обычный LaTeX:
`$v_0 = \sqrt{2gh}$` внутри строки, `$$ ... $$` — отдельной строкой по
центру. Отдельным полем прикладывается **рисунок к условию** (схема или
график) с подписью.

Максимального балла в форме нет намеренно: участникам он не показывается,
а шкалу удобнее выставлять уже при проверке.

### Как одобрить задачу

**На сайте:** «Дистанционный тур» → «Задачи» → открыть задачу. Внизу
формы у администратора блок «Решение администратора»:

* **Сохранить и одобрить** — можно заодно поправить условие;
* **Вернуть на доработку** — только с комментарием, автор увидит его
  у себя в форме задачи;
* **Только сохранить** — правка без смены статуса.

То же в админке: **Задачи** → отметить галочками → действие
**«Одобрить выбранные задачи»**.

### Как назначить дополнительных проверяющих

По умолчанию решения задачи проверяет её автор. Чтобы добавить других:
Админка → **Задачи** → открыть задачу → поле **дополнительные проверяющие**
→ выбрать организаторов. Они увидят решения этой задачи в своей очереди.

Организатор, которого не назначили, чужие решения не откроет.

### То же самое в админке

Админка → **Задачи** → **Добавить задачу**.

| Поле | Что писать |
|---|---|
| **Этап** | к какому этапу относится (например, «Дистанционный первый отборочный этап») |
| **Номер** | порядковый номер в этапе, по нему сортируется список |
| **Название** | видно участникам в списке |
| **Условие** | текст условия, формулы в долларах |
| **Максимальный балл** | сколько даётся за полное решение |
| **Статус** | «Одобрена» — участники увидят задачу с начала этапа |

Внизу, в блоке **Материалы к задаче**, прикладываются данные:
`signal.txt`, таблицы, картинки. Столько файлов, сколько нужно.

### Как выложить разбор

У той же задачи: поле **разбор (PDF)** и **разбор доступен с**.
Разбор не покажется участникам, пока не наступит указанная дата —
даже если файл уже загружен. Так можно залить разборы заранее.

### Порядок публикации целого этапа

1. Проверить этап: **Сезоны → Этапы**. Поле «начало» — это момент, когда
   откроются все задачи этапа и начнётся приём решений.
2. Заранее завести и одобрить все задачи.
3. В назначенный час задачи появятся сами. Вставать ночью не нужно.

## 5. Как проверять решения

Есть два пути. **Основной — на самом сайте**, без захода в админку.

### На сайте (рекомендуется)

Войдите как организатор → на вкладках «Дистанционный тур» и «Очный тур»
сверху появится панель «Организатору» → **Проверить решения**
(или сразу `/online/review/`).

Очередь открывается сразу на непроверенных. Фильтры — по задаче и по
статусу. «Проверить →» открывает страницу, где слева файлы решения и
комментарий участника, справа форма оценки: балл, комментарий, статус.
После сохранения вас возвращает в ту же очередь с теми же фильтрами,
чтобы проверять подряд.

Балл выше максимума за задачу форма не примет: опечатка «100» вместо «10»
иначе молча испортит итоговую таблицу.

Комментарий увидит участник, так что пишите по делу — что именно не зачтено.

### В админке

Админка → **Решения**.

Справа — фильтры. Рабочий сценарий проверяющего:

1. Фильтр **«задача»** → выбрать, например, задачу 8.
2. Фильтр **«последняя попытка» = Да** — иначе увидите и черновики.
3. Фильтр **«статус проверки» = Не проверено**.

Открыть решение. Внутри:

* **Файлы решения** — скачать PDF и код;
* блок **Оценка** — поставить балл, написать комментарий, статус
  «Проверено».

Комментарий увидит участник после публикации результатов, так что пишите
по делу: что именно не зачтено.

Поля «участник», «задача» и «после дедлайна» изменить нельзя — это защита
от случайной правки.

На странице решения видны и предыдущие попытки того же участника: если
возникнет спор, сразу понятно, что и когда отправляли.

### Про повторные загрузки

Участник может перезаливать решение до дедлайна. Каждая попытка сохраняется,
но зачитывается **последняя** — у неё стоит галочка «последняя попытка».
Старые версии остаются: если возникнет спор, видно, что и когда отправляли.

Решения, отправленные после дедлайна, помечаются красным «после дедлайна».
Они не удаляются — решение, принимать их или нет, остаётся за вами.

## 6. Как пустить человека проверять решения

Отдельной роли «жюри» нет: проверяют организаторы. Кто именно —
решается правами, а не ролью.

Один раз за проект создайте группу прав:

1. Админка → **Группы** → **Добавить группу**, название «Проверяющие».
2. Выдать права:
   * `contest | решение | Can view submission`
   * `contest | оценка | Can add grade`
   * `contest | оценка | Can change grade`
   * `contest | оценка | Can view grade`
3. Больше ничего не давать.

Дальше каждому проверяющему: роль «Организатор», флаг **«Статус персонала»**
и членство в группе «Проверяющие». Тогда он войдёт в админку и увидит
только решения и оценки — ни задач, ни пользователей, ни сроков.

## 7. Как отправить рассылку

Админка → **Рассылки** → **Добавить рассылку**.

1. Тема и текст. В тексте работает `{{ first_name }}` — подставится имя.
2. **Кому** — выбрать аудиторию. Самые полезные:
   * «Зарегистрированные, но ничего не сдавшие» — напомнить о дедлайне;
   * «Записавшиеся на очный тур» — прислать адрес площадки.
3. Для аудиторий по сезону обязательно выбрать **сезон**.
4. Сохранить. В поле «получатели» сразу видно, скольким уйдёт письмо.
5. Кнопка **«Отправить рассылку»** вверху справа → страница подтверждения
   с числом получателей и предпросмотром → подтвердить.

Письма уходят порциями в фоне. Кому дошло, а кому нет — видно в
**Рассылки → Письма**.

На сервере письма отправляет контейнер `mailer`, он запускается вместе с сайтом.

## 8. Лекции и плейлисты

### Одна лекция

Контент → **Лекции** → Добавить. В поле **ссылка на видео** вставьте адрес
**одного видео** из строки браузера — ВКонтакте, YouTube или Rutube.
Видео заиграет прямо на странице лекции.

Ссылка на плейлист сюда не годится: такой плеер не встраивается.
Для плейлистов есть отдельный раздел.

### Темы лекций

Лекций за шесть сезонов больше полусотни, поэтому в архиве они разложены
по разделам (**физика**, **программирование**, **общее**) и темам внутри
них: «Небесная механика и баллистика», «Основы Python», «Разборы задач».

Темы заводятся в админке: **Контент → Темы лекций**. У темы указывается
раздел — лекция берёт раздел от своей темы, отдельно его ставить не надо.
Тему лекции выбирают в её карточке.

Если лекции не поставить тему, она попадёт в конец, в группу «Прочее».

**Добавить лекцию может организатор прямо на сайте:** вкладка «Лекции» →
панель «Организатору» → **Добавить лекцию**. Дальше всё как с задачами:
черновик или «отправить на одобрение», участники видят лекцию только
после того, как администратор её одобрит (Админка → Лекции → действие
«Одобрить выбранные лекции»).

Ссылка на плейлист в форме не принимается: из неё не собирается
проигрыватель, и на странице лекции было бы пусто. Форма скажет об этом
сразу, а не после публикации.

### Плейлисты

Контент → **Плейлисты**. Название, ссылка, сезон.

**Сезон** важен: по нему на карточке появляется метка «Сезон 2023/24»,
и плейлист попадает в нужный год архива. Год можно менять прямо в списке.

Обложки для YouTube подтягиваются автоматически:

```bash
python manage.py fetch_playlist_covers
```

У ВКонтакте превью программно не достать — загрузите картинку вручную
в поле «превью» или оставьте пустым: тогда покажется иконка плейлиста.

## 8.5. Очный тур: списки участников и баллы

Вкладка **«Очный тур»** → панель «Организатору» → у своей площадки ссылки
**участники** и **итоги**.

Со страницы площадки организатору доступны четыре действия:
**Участники и баллы**, **Итоговая таблица**, **Редактировать**,
**Написать участникам**.

### Правка своей площадки

**Редактировать** — можно менять всё, включая точку на карте. Чаще всего
правят описание: «вход со двора», «сбор в 9:30», «взять паспорт». Просить
об этом администратора не нужно.

Статус при правке не сбрасывается: одобренная площадка не пропадёт с
карты из-за исправленной опечатки.

**Регион** выбирается из списка, а не пишется руками. Когда вы отмечаете
точку на карте, Яндекс определяет по ней адрес и сверяет с выбранным
регионом и городом — если они расходятся, под картой появляется
предупреждение. Это ловит промах по карте, который иначе всплыл бы,
когда школьник приедет не туда. Предупреждение не блокирует сохранение:
бывают спорные случаи с границами округов.

**Контакт площадки** — имя и телефон **или** телеграм, хотя бы одно.

### Письмо участникам своей площадки

**Написать участникам** — форма с темой и текстом. Перед отправкой видно,
скольким уйдёт и кому именно. В тексте работает `{{ first_name }}` —
подставится имя.

Письма уходят через тот же механизм, что и общие рассылки, поэтому
повторное нажатие никому не пришлёт письмо дважды, а результат виден в
админке: **Рассылки → Письма**.

Написать можно только участникам своей площадки — чужие списки закрыты.

### Ведомость

**Ведомость** (`Участники и баллы`) — таблица: строка на участника, столбец на
задачу. Впишите баллы прямо в клетки и нажмите «Сохранить баллы». Пустая
клетка означает, что задача не сдавалась или не проверена; дробные баллы
можно писать через точку или запятую. Сумма пересчитывается при сохранении.

**Итоги** — та же таблица, отсортированная по сумме, с местами.

Свою площадку видит только её организатор (поле **организаторы** в
карточке площадки) и администраторы. Чужие списки закрыты: это
персональные данные школьников.

### Когда участники увидят баллы

Не сразу. Пока идёт заполнение ведомости, баллы видны только организаторам,
а участник видит в кабинете пометку «скоро».

Открывает баллы **администратор** кнопкой **«Опубликовать результаты
участникам»** на странице ведомости. Кнопка работает на весь этап, а не на
одну площадку, и нажимается, когда ведомости готовы целиком. Той же кнопкой
результаты можно снова скрыть.

Организатор опубликовать результаты не может — это решение по всей
олимпиаде, а не по одной школе.

## 8.7. Страницы «Второй тур» и «Финал»

Эти два этапа не проводятся на нашем сайте, поэтому у них нет ни задач,
ни площадок — только страницы с описанием. Тексты правятся в админке,
без программиста.

**Второй тур** (`/second/`) — уже написано, что тур идёт с прокторингом
на exams.mipt.ru и что подробности с приглашениями будут позже. Если
нужно добавить своё, впишите в **Сезоны → Этапы → Второй тур →
описание**: этот текст появится под готовым блоком.

Ссылка на платформу берётся из поля **внешняя платформа** того же этапа.

**Финал** (`/final/`) — текст о том, как проходит финал, пишется в
**Сезоны → Этапы → Финал → описание**. Пока поле пустое, на странице
стоит короткая заглушка.

### Фотографии финалов

Если снимков много и они лежат в папке файлами вида `sez1.png`,
`sez2.png` (номер = номер олимпиады), загрузите их одной командой:

```bash
python manage.py import_photos albums/
```

Команда разложит их по сезонам и не задвоит при повторном запуске.

По одной: админка → **Фотографии** → Добавить. Поля: сам снимок, подпись и
**сезон** — по нему на карточке появляется год («АО VI»). Подпись, год и
порядок можно править прямо в списке, не открывая каждую фотографию.

Снимки хранятся у нас, а не ссылками на внешний альбом: альбомы
переезжают и закрываются, а архив олимпиады должен это пережить.
Помните, что фотографии попадают в резервную копию каталога `media/`.

## 8.9. Проверка согласий на обработку персональных данных

Участник загружает скан подписанного согласия в кабинете — и сразу
получает доступ к участию. Проверка ручная:

1. Админка → **Пользователи → Согласия на обработку ПД**, фильтр
   «статус: На проверке».
2. Открыть согласие → ссылка **скан** откроет файл в новой вкладке, ниже —
   данные, которые были вписаны в бланк. Сверить: те же ФИО и документ,
   есть подпись, для несовершеннолетнего подписал представитель.
3. Всё в порядке — статус **«Принято»** (или галочками в списке и действие
   «Принять выбранные согласия»).
4. Что-то не так — статус **«Нужно переслать»** и комментарий: что
   исправить. Без комментария не сохранится. Участнику уйдёт письмо,
   в кабинете появится просьба загрузить заново. Участие при этом не
   закрывается.

Статус **«Устарело»** ставится сам, если участник поменял данные документа
после загрузки: нужен новый скан, до него участие закрыто.

Анкеты, паспортные данные и сканы видят **только администраторы** —
организатору эти разделы недоступны, даже если ему выданы права в админке.

Тексты бланков: **Контент → Страницы** → `consent-form-minor` (подписывает
представитель) и `consent-form-adult` (участнику 18+). Данные подставляются
на место `{{ participant_name }}`, `{{ parent_document }}` и т. п. — список
подстановок в начале раздела бланков в `apps/core/legal_templates.py`.

## 9. Где лежат решения участников

Файл, который загрузил участник, попадает на сервер в

```
media/solutions/<сезон>/problem-<номер задачи>/user-<id участника>/<имя файла>
```

В базе хранится только путь к файлу, сам файл лежит на диске. Это важно
для двух вещей:

* **бэкап** должен включать и базу, и каталог `media/` — по отдельности
  они бесполезны (см. [deploy.md](deploy.md));
* при переносе на другой сервер каталог `media/` переезжает целиком.

Скачать решение можно из админки: **Решения** → открыть → блок
**Файлы решения**.

### Проверить, что отправка работает

На странице «Дистанционный тур» внизу есть **тренировочная задача**.
Она открыта всегда, вне зависимости от сроков туров, и на результаты не
влияет — загрузите в неё любой файл и убедитесь, что решение дошло.

Тренировочные решения видны там же, где обычные (Решения), и их можно
удалять в любой момент. Сама задача живёт в служебном этапе
«Тренировочная задача» с галочкой «тренировочный»: из-за неё этап не
показывается ни на схеме, ни как текущий тур.

## 10. Что настраивается только в коде

Почти всё делается из админки, но не всё:

| Нужно | Где |
|---|---|
| Новое поле в анкете участника | код + миграция |
| Новый раздел сайта | код |
| Цвета и шрифты | `static/css/tokens.css` (файл дизайнера) |
| Телеграм-канал, почта поддержки, ключ Яндекс.Карт | `.env` |
| Список регионов в анкете | `apps/accounts/regions.py` |
| Даты этапов нового сезона | `apps/seasons/schedule.py` — но менять их проще в админке |

Карта переключается одной строкой: есть `YANDEX_MAPS_API_KEY` — рисует
Яндекс, пусто — OpenStreetMap.

Подробнее — в [roles.md](roles.md).
