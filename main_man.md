
# Техническое задание: схема проведения олимпиады на главной странице

Нужно реализовать на центральной странице существующего Django-сайта компактную горизонтальную интерактивную схему проведения олимпиады.

Основной принцип — минималистичная горизонтальная последовательность из четырех кликабельных панелей:

**Очный этап → Дистанционный этап → Второй тур → Финал**

При этом первые два этапа не являются последовательными: школьник может участвовать в очном этапе, дистанционном этапе или в обоих. Это нужно показать текстом и группировкой, но не усложнять схему развилками и стрелками.

---

## 1. Содержательная структура

Олимпиада состоит из отборочного и заключительного туров.

### Отборочный тур

Первый уровень отбора включает два равнозначных формата участия:

1. **Очный этап**

   * даты: **19–24 октября**
   * иконка: школа / учебное здание
   * отдельная кликабельная панель

2. **Дистанционный этап**

   * даты: **15 ноября — 15 января**
   * иконка: компьютер / ноутбук
   * отдельная кликабельная панель

Участник может пройти только один из этих этапов либо оба.

После них:

3. **Второй тур**

   * даты: **14 и 28 февраля**
   * дистанционный формат с контролем проведения
   * на самой схеме слово «прокторинг» пока не использовать
   * иконка: несколько связанных компьютеров / компьютерная сеть
   * отдельная кликабельная панель

### Заключительный тур

4. **Финал**

   * даты: **12–16 апреля**
   * проводится очно
   * место: **кампус МФТИ**
   * иконка: стилизованное здание / кампус
   * отдельная кликабельная панель

---

# 2. Основная визуальная концепция

Нужна именно горизонтальная схема из четырех карточек:

```text
┌──────────────┐  ┌──────────────────┐  ┌──────────────┐  ┌──────────────┐
│      🏫      │  │        💻        │  │      🖧      │  │      🏛      │
│ Очный этап   │  │ Дистанционный    │  │ Второй тур   │  │ Финал        │
│ 19–24 окт.   │  │ 15 ноя — 15 янв.│  │ 14 / 28 фев. │  │ 12–16 апр.   │
└──────────────┘  └──────────────────┘  └──────────────┘  │ Кампус МФТИ  │
                                                          └──────────────┘
```

Карточки должны быть визуально равнозначными по размеру и стилю.

Не нужно делать сложную временную шкалу, развилки, соединительные линии или декоративную инфографику.

Основная структура должна читаться за несколько секунд.

---

# 3. Вложенные цветовые области

За карточками необходимо реализовать систему из **трех вложенных прямоугольных фоновых областей**.

Это один из основных элементов дизайна.

Логика следующая.

## Самая внутренняя область

Объединяет:

* Очный этап
* Дистанционный этап

Это два равнозначных варианта прохождения первого этапа отбора.

Использовать здесь **наиболее выраженный / акцентный цвет платформы**.

Схематически:

```text
╔══════════════════════════════════╗
║  [Очный этап] [Дистанционный]   ║
╚══════════════════════════════════╝
```

Важно: фон должен группировать эти карточки, но сами карточки должны оставаться хорошо различимыми.

Если основной акцентный цвет платформы слишком насыщенный для большой площади, допустимо использовать его осветленный вариант либо небольшую прозрачность.

---

## Средняя область

Объединяет:

* Очный этап
* Дистанционный этап
* Второй тур

То есть визуально показывает весь **отборочный тур**.

Фон должен быть **светлее и менее насыщенным**, чем внутренняя область.

Получается вложенная структура:

```text
┌──────────────────────────────────────────────────────┐
│                                                      │
│   ╔══════════════════════════════════╗               │
│   ║ [Очный]       [Дистанционный]   ║ [Второй тур] │
│   ╚══════════════════════════════════╝               │
│                                                      │
└──────────────────────────────────────────────────────┘
```

Над этой областью или внутри нее необходимо разместить небольшой заголовок:

**Отборочный тур**

Заголовок не должен конкурировать по размеру с названиями карточек.

---

## Самая внешняя область

Объединяет:

* весь отборочный тур;
* финал.

Она должна иметь **самый светлый фон**.

Схематически:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   ┌─────────────────────────────────────────────────────┐                  │
│   │ Отборочный тур                                     │                  │
│   │                                                     │                  │
│   │   ╔══════════════════════════════╗                  │  ┌───────────┐  │
│   │   ║ [Очный] [Дистанционный]     ║ [Второй тур]    │  │  Финал    │  │
│   │   ╚══════════════════════════════╝                  │  │           │  │
│   └─────────────────────────────────────────────────────┘  └───────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

Таким образом цветовая иерархия должна быть:

**акцентный / наиболее насыщенный**
→ первые два равнозначных этапа;

**более светлый**
→ весь отборочный тур;

**самый светлый**
→ вся олимпиада вместе с финалом.

Не задавать конкретные HEX-цвета в компоненте, если в проекте уже существуют CSS variables / design tokens.

Следует использовать существующую палитру платформы.

Например:

```css
var(--color-accent)
var(--color-accent-light)
var(--color-accent-extra-light)
```

или соответствующие уже существующие переменные проекта.

Если таких переменных нет, создать локальные переменные компонента, но подобрать значения на основе существующей палитры сайта.

# 4. Карточки этапов

Каждый этап — отдельная кликабельная панель.

Внутри каждой панели:

1. крупная минималистичная иконка;
2. название этапа;
3. даты;
4. для финала дополнительно:
   **Кампус МФТИ**.

Пример:

```text
      🏫

   Очный этап

 19–24 октября
```

Для финала:

```text
      🏛

     Финал

  12–16 апреля
  Кампус МФТИ
```

---

# 5. Иконки

Стиль нужен максимально простой.

Не использовать фотографии, сложные иллюстрации, изображения людей или детализированные рисунки.

На первом этапе допускаются обычные emoji как заглушки.

Примерная семантика:

### Очный этап

Школа / учебное здание:

```text
🏫
```

или SVG-аналог здания.

### Дистанционный этап

Компьютер:

```text
💻
```

### Второй тур

Нужна семантика компьютерной сети.

Emoji-подходящей пиктограммы практически нет, поэтому предпочтительно использовать простую SVG-иконку:

* несколько мониторов;
* несколько компьютеров, соединенных линиями;
* network;
* network-nodes;
* screens;
* monitor-network.

Если в проекте используется Lucide / Font Awesome / другая библиотека, взять из нее максимально близкую иконку.

### Финал

Здание кампуса:

```text
🏛
```

или SVG типа:

* university;
* landmark;
* building-columns.

Иконка финала должна восприниматься именно как физическое место проведения, а не как абстрактный кубок.

Не использовать trophy как основную пиктограмму.

---

# 6. Подпись о равнозначности первых двух этапов

Нужно явно объяснить, что первые два этапа являются альтернативными способами участия.

Под первыми двумя карточками внутри внутренней группы разместить небольшую подпись:

**Можно участвовать в одном или обоих этапах**

Она должна быть визуально второстепенной.

Например:

```text
┌─────────────────────────────────────────┐
│                                         │
│    [Очный этап]   [Дистанционный этап] │
│                                         │
│  Можно участвовать в одном или обоих   │
│               этапах                    │
│                                         │
└─────────────────────────────────────────┘
```

Не использовать между карточками надпись «ИЛИ», потому что фактически допустим вариант участия в обоих этапах.

Также не следует рисовать стрелку от очного этапа к дистанционному: она создаст ошибочное впечатление последовательного прохождения.

---

# 7. Кликабельность

Все четыре панели должны быть полноценными ссылками.

То есть:

```html
<a href="..." class="olympiad-stage">
    ...
</a>
```

а не:

```html
<div onclick="...">
```

URL всех четырех страниц уже существуют в проекте.

Агент должен найти существующие Django URL names и использовать:

```django
{% url '...' %}
```

Не хардкодить URL вида:

```html
href="/olympiad/..."
```

если в проекте существуют именованные Django routes.

---

# 8. Hover

При наведении пользователь должен очевидно понимать, что панель кликабельна.

Достаточно очень легкого эффекта:

```css
transform: translateY(-2px);
```

и/или:

```css
box-shadow
```

и небольшого изменения:

```css
border-color
```

или фона.

Не использовать:

* прыгающие иконки;
* мигающие элементы;
* двигающиеся стрелки;
* сложные transition;
* scaling более чем примерно 1.01–1.02.

Схема должна оставаться спокойной.

# 11. CSS-layout

Для desktop основной контейнер удобно реализовать через CSS Grid.

Логически:

```text
primary group | second round | final
```

а внутри `primary group`:

```text
offline | online
```

Примерная идея:

```css
.olympiad-scheme__all {
    display: grid;
    grid-template-columns: minmax(0, 3fr) minmax(180px, 1fr);
}

.olympiad-scheme__qualifying {
    display: grid;
    grid-template-columns: minmax(0, 2fr) minmax(180px, 1fr);
}

.olympiad-scheme__primary {
    display: grid;
    grid-template-columns: repeat(2, minmax(0, 1fr));
}
```

Конкретные значения подогнать под существующую ширину контента сайта.

Карточки по возможности должны иметь одинаковую высоту.

Использовать:

```css
align-items: stretch;
```

# 12. Отступы и форма

Вся схема должна выглядеть как один аккуратный блок.

Предпочтительно:

* одинаковый `border-radius` у фоновых контейнеров;
* немного меньший radius у карточек;
* достаточно воздуха вокруг карточек;
* небольшие промежутки между ними.

Например концептуально:

```text
outer padding: 12–20 px
gap between stages: 8–16 px
card padding: 16–24 px
```

Конкретные значения взять из spacing-системы текущей платформы.

Если на сайте везде используются прямоугольники с небольшим радиусом — не делать здесь pill-shaped элементы.

Компонент должен выглядеть частью существующего сайта, а не отдельной инфографикой.

---

# 13. Иерархия текста

Название этапа — наиболее заметный текст внутри карточки.

Например:

```css
font-weight: 600;
```

Даты немного меньше.

Название тура:

```text
ОТБОРОЧНЫЙ ТУР
```

должно быть визуально вспомогательным:

* небольшой размер;
* medium / semibold;
* возможно uppercase;
* небольшой letter-spacing, если такой стиль уже применяется на сайте.

Не следует писать крупный заголовок «Первый этап отбора».

Достаточно самих группировок.

---

# 14. Стрелки

Можно использовать небольшие стрелки между:

```text
[первые два этапа] → [Второй тур] → [Финал]
```

Но они не должны быть обязательной частью геометрии.

Важно:

между:

```text
Очный этап
```

и:

```text
Дистанционный этап
```

стрелки быть не должно.

Если используются стрелки, схема должна выглядеть примерно так:

```text
╔══════════════════════════════╗
║ [Очный]     [Дистанционный] ║
╚══════════════════════════════╝
               →
        [Второй тур]
               →
           [Финал]
```

В desktop они, разумеется, располагаются горизонтально.

Стрелки должны быть маленькими и нейтральными.

На маленьком экране не пытаться уменьшить четыре карточки до микроскопического размера.

При ширине примерно ниже `768px` или существующего breakpoint проекта перейти в вертикальную компоновку.

Например:

# 17. Accessibility

Каждая карточка должна быть `<a>`.

Должна работать навигация клавишей Tab.

Обязательно нормальное состояние:

```css
:focus-visible
```

например рамка:

```css
outline: 2px solid var(--color-accent);
outline-offset: 2px;
```

Если используются SVG:

```html
aria-hidden="true"
```

поскольку название этапа уже присутствует текстом.

Не помещать названия и даты внутрь SVG.

# 18. Что не нужно делать

Не добавлять:

* индикатор текущего этапа;
* `active / completed / upcoming`;
* таймер;
* countdown;
* прогресс-бар;
* номера этапов 1–4;
* анимацию прохождения;
* фотографии;
* иллюстрации школьников;
* кубок;
* медаль;
* confetti;
* сложные линии между блоками;
* дополнительный текст с правилами.

На главной странице нужна именно компактная навигационная схема.

Подробные правила находятся на соответствующих страницах, куда ведут карточки.

---

# 19. Итоговый текст карточек

Использовать следующие подписи.

### Карточка 1

```text
🏫

Очный этап

19–24 октября
```

### Карточка 2

```text
💻

Дистанционный этап

15 ноября — 15 января
```

Под группой:

```text
Можно участвовать в одном или обоих этапах
```

### Карточка 3

```text
[иконка сети компьютеров]

Второй тур

14 и 28 февраля
```

### Карточка 4

```text
🏛

Финал

12–16 апреля

Кампус МФТИ
```

# 20. Общий визуальный приоритет

Главный смысл дизайна:

```text
Первый уровень отбора
[Очный] [Дистанционный]

            ↓

Весь отборочный тур
[Очный] [Дистанционный] [Второй тур]

            ↓

Вся олимпиада
[Очный] [Дистанционный] [Второй тур] [Финал]
```

Эта логика должна читаться в первую очередь за счет **вложенных цветных прямоугольников**, а не дополнительного текста.

В результате на главной странице должен получиться один компактный горизонтальный блок, который одновременно:

1. показывает последовательность олимпиады;
2. показывает равнозначность очного и дистанционного первых этапов;
3. показывает, что Второй тур относится к отборочному туру;
4. визуально отделяет Финал;
5. показывает даты;
6. служит навигацией на страницы всех четырех этапов;
7. сохраняет минималистичный стиль существующей платформы.
